# 表紙（公開層）の仕様と引き継ぎ

更新：2026-09-05。今回のユーザー指定は、公開層を「育つ教科書」の表紙にすること。以前のコピペ導線は内側の案内候補として残し、公開表紙の主役にはしない。

## 実装済み

- ソースはリポジトリ直下の `index.html`。コンセプト→育て方→目次→更新履歴→参加方法の順。
- 目次には章タイトルのみ。本文、プロンプト、PDFの埋め込みはない。
- 更新履歴の正本はルートの `changelog.md`。1行を `日付｜回｜内容｜きっかけ` の4項目で管理する。空行は無視する。区切り文字の全角「｜」を本文に含めない。
- `npm run cover:build` で `scripts/build-cover.mjs` が履歴を読み込み、`cover-dist/index.html` を生成する。更新履歴はHTMLへ手書きしない。生成物はGit管理しない。
- 新しい日付を先に表示。同日はファイル内の順序を保つ。実在しない日付や4項目以外の行はビルドエラー。本文はHTMLエスケープする。
- ユーザー提供の2026-09-04の6件を収録。「一末模様」は文脈から「市松模様」に修正。「新設予定」は予定のまま記載。
- もちスラくまの完成済み画像とアイコンを再利用。h1は1個、各セクションはh2。画像alt、スキップリンク、フォーカス輪郭、狭い画面向けCSSを用意。
- `npm run cover:dev` は http://127.0.0.1:4173 を開く。ルートを読み込むたびに履歴を再生成する。
- 通常のビルドでは目次を同一サイト内のパスにする。本人限定の別環境で表紙だけを見る場合のみ、MEMBER_ORIGINに既存教材サイトのHTTPS originを設定できる。

## 今回の確認

`npm run cover:test` の5件が成功。並び順、不正形式の拒否、HTMLエスケープ、セクション順序、changelogだけの編集が生成HTMLへ反映されることを検証。`cover:build`成功、ローカルHTTP 200を確認。

実ブラウザでのクリック、画面幅変更、文字拡大は未確認。ユーザー指定の `frontend-spec-ja.md` は今回のチェックアウトと確認した関連保存先で見つからず、厳密な適合は未確認。現在の配色を引き継ぎ、本文16px、補助情報14px程度、フォーカス表示ありで仮実装している。

## 公開切り替え前の未完了事項

ここは「表紙だけを鍵の外に置く」運用をまだ保証していない。今回の成果は独立した表紙とビルド処理であり、既存Workers本体のルーティング・認証・公開デプロイ設定は変更していない。

確認したコードでは、現在の合言葉は `/skills` とskill-downloadの保護用。他の教材と `public/downloads` は同じ鍵の対象になっていない。リンクを隠すだけでは保護にならない。公開する前に、合言葉の流用方針を確認し、サーバーで教材・API・PDFなどの直接アクセスも確認する。Cloudflareの静的アセットがWorkerを経由せず配信される設定にも注意する。

既存の `/setup` と `/lessons/01`、`/prompt-maker`、`/skills`、`/archive` へのパスは確認済み。第2回の予定欄へリンクするため `#lesson-02` のIDだけ追加した。`/faq` は現在のチェックアウトに存在しない。ユーザー指定のFAQがある別の保存先を確認して統合すること。更新履歴はユーザー提供原稿であり、記載のFAQをこのチェックアウトで公開済みと確認したものではない。

## 質問から追加した節のラベル

対象は、ユーザー指定のFAQ「絵柄や年代の知識がなくても大丈夫？」「背景は透明が正解？黒い背景に見えるのは？」。それぞれ見出し直下に次のように配置する。

```tsx
<h2 id="style-question">絵柄や年代の知識がなくても大丈夫？</h2>
<QuestionOrigin lesson={1} />
```

`components/QuestionOrigin.tsx` と共通CSSにラベルを用意した。対象FAQ本文が見つからないため、実際の見出し直下への挿入は未実施。他の既存節へ質問由来のラベルを推測で貼らない。

## Claudeが続ける順序

1. `frontend-spec-ja.md` と現在のFAQ・鍵の実装場所を確認し、この表紙と突き合わせる。
2. FAQの2つの見出しにQuestionOriginを挿入。既存本文を保つ。
3. 表紙index.htmlを既存サイトの `/` で配信するようビルドとルーティングを接続。現在のアプリ用buildコマンドとは自動接続していない。
4. 表紙と必要最小限の表紙用アセットだけを公開し、教材・PDFを含む内側は同じ鍵で保護する。匿名・正しい鍵・誤った鍵で直接URLも検証する。
5. 実ブラウザで目次、参加リンク、フォーカス、スマホ幅、拡大表示を確認してから公開切り替えを行う。

参考：[Cloudflare公式・Workerを経由する静的アセットのルーティング](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)。今回の公開用ソースには本人限定URL、配置設定、認証情報を含めない。
